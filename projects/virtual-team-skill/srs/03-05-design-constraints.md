# Software Requirements Specification — §3.5 Design Constraints
## Virtual Team Skill

Design constraints are requirements imposed on the system by external factors — organizational decisions, technology standards, compatibility requirements — that restrict how the system may be designed and implemented. These are not optional; violating a design constraint invalidates the implementation.

---

## 3.5.1 Execution Environment Constraint

**DC-01**: The skill shall be implemented exclusively as Claude Code skill files (`.md` format) and shall run only within the Claude Code CLI execution environment. No alternative runtime (standalone Python scripts, Docker containers, CI/CD pipelines, web servers) is permitted in v1.

**Rationale:** The system's core value proposition is that it extends Claude Code natively. Requiring a separate runtime would add installation complexity incompatible with the tool's positioning as a lightweight CLI skill.

---

## 3.5.2 Agent Orchestration Constraint

**DC-02**: The orchestrator and all role agents shall use only Claude Code's native built-in tools for all operations:

| Tool | Permitted usage |
|---|---|
| `Agent` tool | Orchestrator: spawn role agents; Role agents: spawn sub-agents (depth ≤ 2) |
| `Read` tool | Any agent: read artifact files and context |
| `Write` tool | Any agent: write artifact files to disk |
| `Glob` tool | Any agent: discover existing artifact files |
| `Grep` tool | Any agent: search artifact content |
| `TodoWrite` tool | PM Agent: create and update task tracking entries |
| `Skill` tool | Orchestrator: invoke role skill files |

No Python subprocess calls, no external CLI tools (curl, jq, git), no MCP server calls are permitted in v1.

---

## 3.5.3 Model Assignment Constraint

**DC-03**: Agent model assignment shall be fixed per role and shall not be configurable at runtime in v1. The following assignments are mandatory:

| Role Agent | Model | Justification |
|---|---|---|
| TechLead Agent | `claude-opus-4-8` | Deep reasoning required for architectural decisions and trade-off analysis |
| QA/QC Agent | `claude-opus-4-8` | Comprehensive cross-artifact review requires highest reasoning quality |
| BA Agent | `claude-sonnet-4-6` | Balanced quality and cost for requirement analysis and story generation |
| BE Dev Agent | `claude-sonnet-4-6` | Strong code generation; cost-effective for longer code output |
| FE Dev Agent | `claude-sonnet-4-6` | Strong code generation; cost-effective for longer code output |
| Tester Agent | `claude-sonnet-4-6` | Good test case derivation from acceptance criteria |
| PM Agent | `claude-haiku-4-5` | Fast coordination and planning; low reasoning overhead |

Sub-agents spawned by role agents inherit the parent agent's model unless the parent explicitly specifies otherwise in the sub-agent prompt.

---

## 3.5.4 Sub-agent Depth Constraint

**DC-04**: The maximum agent invocation depth shall be two levels:
- Level 1: Role agents (BA, TechLead, PM, BE Dev, FE Dev, Tester, QA/QC) spawned by the orchestrator
- Level 2: Sub-agents spawned by role agents for deep-dive or parallel sub-tasks

Sub-agents (Level 2) shall not invoke the Agent tool. Skill instructions for role agents must explicitly prohibit sub-agent tool use of the Agent tool.

---

## 3.5.5 Output Format Constraint

**DC-05**: All human-readable artifact files shall be written in Markdown format (`.md`). Diagrams embedded in Markdown files shall use Mermaid syntax (`\`\`\`mermaid` code fences). No binary, PDF, DOCX, Excel, or proprietary format artifacts shall be produced by any agent in v1.

**DC-06**: Code artifacts (generated by BE Dev and FE Dev agents) shall be written as source files in the programming language appropriate to the tech stack specified in `tech-stack.md`. The file extension shall match the language (e.g., `.ts` for TypeScript, `.py` for Python). Code artifacts are not Markdown.

---

## 3.5.6 File Path and Storage Constraint

**DC-07**: All skill-generated artifacts shall be stored exclusively within the `projects/` subdirectory of the current working directory. No artifacts shall be written to system directories, the user's home directory (outside the workspace), external storage, or any path outside `projects/{slug}/`.

**DC-08**: All file path references in skill instructions shall use forward-slash separators (`/`). Claude Code's Read and Write tools handle OS-native path resolution. No Windows-specific (`\`) or OS-specific absolute paths shall appear in skill `.md` files.

---

## 3.5.7 No External API Calls Constraint

**DC-09**: Skill instructions shall not include any directives to call external HTTP APIs, command-line tools that make network requests, or remote services beyond the Anthropic Claude API (which is managed by Claude Code). Specifically prohibited:
- GitHub API / GitLab API
- Jira / Linear / Trello API
- Slack / Teams API
- npm registry, pip, or any package manager registry
- Cloud storage APIs (AWS S3, GCP Storage, Azure Blob)
- Any web scraping or HTTP fetch instructions

The Anthropic API is the only permitted network communication channel.

---

## 3.5.8 Credential Security Constraint

**DC-10**: Skill instructions for BA Agent, BE Dev Agent, FE Dev Agent, and QA/QC Agent shall include explicit prohibitions against generating, suggesting, or accepting hardcoded secrets. This is a mandatory instruction element, not optional commentary.

The BE Dev Agent and FE Dev Agent instructions shall include the specific directive: "Do NOT hardcode any credentials, API keys, passwords, tokens, or connection strings. Use environment variable references appropriate to the tech stack (e.g., `process.env.SECRET_NAME`)."

---

## 3.5.9 Cross-platform Compatibility Constraint

**DC-11**: No OS-specific shell commands, path separators, or environment assumptions shall be present in any skill file. Skill instructions shall not assume a specific shell (bash, zsh, PowerShell). Skill instructions that describe file operations shall use Claude Code tool descriptions (Read, Write) rather than shell commands.

**DC-12**: Skill files shall be tested for functional equivalence on:
- Windows 10 / Windows 11 (PowerShell and Git Bash)
- macOS 12+ (Zsh / Bash)
- Ubuntu 20.04+ (Bash)

---

## 3.5.10 Coding Standards for Skill Files

**DC-13**: Agent instructions in skill `.md` files shall be written in English, in imperative voice ("Read the BA artifacts. Analyze requirements. Write the following files..."). Agent instructions shall not use passive voice or suggest optionality for mandatory steps.

**DC-14**: Each skill file shall include an explicit list of required output section headings for each artifact the agent must produce. This list serves as the source of truth for Layer 1 validation schema (see §3.2 FR-34 and Appendix B — TBD-01 resolution).

**DC-15**: The `## Flags from Previous Agents` section shall be listed as a required output section in the skill instructions for TechLead Agent, Tester Agent, and QA/QC Agent. For all other agents it is encouraged but not mandatory.

**DC-16**: ID fields in artifacts shall use zero-padded three-digit numbers:
- User stories: `US-001`, `US-042`
- Business rules: `BR-001`, `BR-012`
- ADRs: `ADR-001`, `ADR-002`
- Test cases: `TC-UNIT-001`, `TC-INT-023`, `TC-E2E-007`
- Flags: `FLAG-TECHLEAD-001`, `FLAG-TESTER-002`

**DC-17**: Markdown artifact files shall use ATX-style headings (`##`, `###`) exclusively. Setext-style headings (`===`, `---`) shall not be used. This ensures consistent heading detection by the Layer 1 validation script.

---

## 3.5.11 No Git Operations Constraint

**DC-18**: Skill instructions shall not include directives to execute any git commands (`git add`, `git commit`, `git push`, `git checkout`, `git branch`, etc.). Generated code is placed in `projects/{slug}/team/be/` and `projects/{slug}/team/fe/` for the operator to manually integrate into their own repository. This constraint exists to prevent unintended irreversible remote operations.
